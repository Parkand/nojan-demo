# نوژان — مدیریت درخواست کالا

وب‌اپ یکپارچه فارسی، راست‌به‌چپ و واکنش‌گرا با تم سفید و قرمز؛ Next.js، React، TypeScript، Prisma و MySQL. بک‌اند جداگانه لازم نیست، اما **سرور Node.js باید هنگام استفاده روشن باشد**؛ این برنامه سایت استاتیک نیست.

## امکانات

- ورود با نام کاربری و رمز عبور؛ نقش‌های `USER` و `ADMIN`.
- مدیریت کاربران، دسته‌بندی‌ها و کالاها توسط مدیر.
- ثبت سفارش چندقلمی، موجودی اعلامی، مقدار مورد نیاز و تاریخ سفارش.
- کاربر فقط سفارش‌های خودش را مشاهده، ویرایش و حذف می‌کند؛ مدیر همه سفارش‌ها را می‌بیند و مدیریت می‌کند.
- تأیید سفارش فقط توسط مدیر؛ سفارش تأییدشده قابل ویرایش یا حذف نیست.
- جستجو، صفحه‌بندی، فیلتر وضعیت سفارش، پیام خطا و تأیید قبل از حذف.
- پنج جدول اصلی: `users`, `categories`, `products`, `orders`, `order_items`؛ جدول فنی `_prisma_migrations` نیز توسط Prisma ساخته می‌شود.
- فیلدهای ردیابی در هر پنج جدول: `id`, `createdAt`, `createdById`, `updatedAt`, `updatedById`, `deletedAt`, `deletedById`.
- حذف نرم؛ هیچ مسیر برنامه‌ای برای حذف فیزیکی وجود ندارد. اقلام جایگزین‌شده هنگام ویرایش سفارش نیز حذف نرم می‌شوند.
- کد کالا، کد دسته‌بندی و نام کاربری حتی پس از حذف قابل استفاده مجدد نیستند.
- حذف دسته‌بندی دارای کالای فعال و حذف/تنزل نقش خود مدیر مجاز نیست.
- رمز هش‌شده با bcrypt، نشست امضاشده ۸ساعته و کوکی HttpOnly؛ تغییر کاربر نشست‌های او را نامعتبر می‌کند.
- محدودیت ورود برای حساب موجود پس از ۵ تلاش ناموفق، به مدت ۱۵ دقیقه.

موجودی صرفاً **اعلامی** است؛ انبارداری، کسر خودکار موجودی، قیمت، فاکتور و پرداخت در محدوده این نسخه نیستند. نمایش تاریخ شمسی است؛ انتخاب تاریخ از ورودی استاندارد مرورگر انجام می‌شود. عنوان و واحد کالا در سفارش از اطلاعات فعلی کالا خوانده می‌شود؛ این نسخه آرشیو مستقل نام/واحد کالا ندارد. فیلدهای ردیابی، تاریخچه کامل همه تغییرات را جایگزین نمی‌کنند.

## پیش‌نیازها

1. Node.js نسخه **22.12 یا بالاتر** همراه npm، ترجیحاً نسخه LTS.
2. MySQL 8 و دیتابیس خالی با کدگذاری `utf8mb4`.
3. اینترنت هنگام نصب وابستگی‌ها. فونت Vazirmatn داخل وابستگی پروژه است و در زمان استفاده از سرویس فونت خارجی بارگیری نمی‌شود.
4. در ویندوز: PowerShell 5.1 یا بالاتر؛ برای نسخه Bash، Git Bash یا WSL.

نصب‌کننده Node.js یا MySQL را نصب نمی‌کند، سرویس ویندوز نمی‌سازد و تنظیمات سیستمی را تغییر نمی‌دهد.

## ۱. ساخت دیتابیس

با حساب مدیریتی MySQL، در MySQL Workbench یا ابزار خط فرمان اجرا کنید. رمز نمونه را **پیش از اجرا** عوض کنید و آن را در فایل عمومی ذخیره نکنید:

```sql
CREATE DATABASE nozhan CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'nozhan'@'127.0.0.1' IDENTIFIED BY 'REPLACE_WITH_A_STRONG_UNIQUE_PASSWORD';
GRANT SELECT, INSERT, UPDATE, CREATE, ALTER, INDEX, REFERENCES
ON nozhan.* TO 'nozhan'@'127.0.0.1';
```

اتصال نصب با میزبان `127.0.0.1`، پورت `3306` و نام دیتابیس/کاربر `nozhan` انجام می‌شود. اگر MySQL شما میزبان کاربر را `localhost` تشخیص می‌دهد، حساب متناظر آن میزبان را بسازید؛ از میزبان `%` برای نصب محلی استفاده نکنید. رمز واردشده در نصب باید دقیقاً رمز همین کاربر باشد.

مجوز `DELETE` داده نشده است تا حذف فیزیکی از حساب برنامه نیز مسدود باشد. مجوزهای ساخت جدول برای مهاجرت اولیه‌اند. برای استقرار واقعی بهتر است حساب مهاجرت جدا باشد و حساب اجرای برنامه فقط `SELECT, INSERT, UPDATE` داشته باشد. برای اجرای مهاجرت‌های آینده ممکن است مجوزهای DDL اضافی لازم شود.

## ۲. نصب یک‌فایلی ویندوز — روش پیشنهادی

فایل `Install-Nozhan.ps1` را دانلود کنید. PowerShell را در پوشه دانلود باز کنید و اجرا کنید:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Install-Nozhan.ps1" -Target "F:\Nexora Nojan"
```

`ExecutionPolicy Bypass` فقط برای همین پردازش است و سیاست دائمی سیستم را تغییر نمی‌دهد. فایل دانلودشده را پیش از اجرا بررسی کنید. دسترسی Administrator لازم نیست، مگر مجوز پوشه مقصد محدود باشد.

نصب‌کننده تمام سورس را در خود دارد و پس از استخراج:

1. وابستگی‌های نسخه‌بندی‌شده را با `npm ci` نصب می‌کند.
2. اطلاعات اتصال MySQL را می‌گیرد و `.env` با کلید نشست تصادفی می‌سازد.
3. Prisma Client و جدول‌ها را می‌سازد (`migrate deploy`، نه `migrate reset`).
4. نام نمایشی، نام کاربری و رمز مدیر اولیه را می‌گیرد؛ رمز پیش‌فرض وجود ندارد.
5. TypeScript و بیلد production را اجرا می‌کند.

رمز مدیر باید ۱۰ تا ۶۴ نویسه و حداکثر ۷۲ بایت باشد. نام کاربری ۳ تا ۶۴ نویسه انگلیسی، عدد، نقطه، خط تیره یا زیرخط است.

**اگر پوشه مقصد وجود داشته باشد، نصب‌کننده قبل از استخراج متوقف می‌شود و چیزی را بازنویسی نمی‌کند.** برای فقط استخراج سورس، پارامتر `-ExtractOnly` را اضافه کنید.

اگر نصب پس از استخراج متوقف شد، پوشه را پاک نکنید؛ مشکل اینترنت یا دیتابیس را رفع کنید و ادامه دهید:

```powershell
Set-Location "F:\Nexora Nojan"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1"
```

فایل `.env` موجود حفظ می‌شود و مدیر فعال موجود دوباره ساخته نمی‌شود. پس از نصب موفق وابستگی‌ها می‌توانید برای ادامه از `-SkipInstall` استفاده کنید. برای اصلاح اتصال، `.env` را ویرایش کنید.

## نصب با Bash

Git Bash در ویندوز:

```bash
bash ./Install-Nozhan.sh "/f/Nexora Nojan"
```

در WSL مسیر معادل `/mnt/f/Nexora Nojan` است. در لینوکس مسیر دلخواه بدهید. فایل مستقل Bash نیز شامل تمام سورس است. برای فقط استخراج، آرگومان دوم `--extract-only` است. برای ادامه نصب متوقف‌شده:

```bash
cd "/f/Nexora Nojan"
bash setup.sh
# در صورت نصب کامل وابستگی‌ها: bash setup.sh --skip-install
```

وابستگی‌های نصب‌شده در Windows و WSL را مشترک استفاده نکنید؛ باینری‌های Prisma و Next.js وابسته به سیستم‌عامل هستند.

## نصب از ZIP

محتویات `Nozhan-Source.zip` را در پوشه مقصد استخراج و `setup.ps1` یا `setup.sh` را اجرا کنید. فایل ZIP شامل `.env.example`، سورس، lockfile، migration و راهنماست؛ شامل رمز، `.env`، `node_modules` یا خروجی بیلد نیست.

## ۳. اجرا

پس از نصب موفق، در PowerShell:

```powershell
Set-Location "F:\Nexora Nojan"
npm.cmd start -- --hostname 127.0.0.1
```

سپس **http://localhost:3000** را باز کنید. ترمینال باید باز بماند؛ `Ctrl+C` برنامه را متوقف می‌کند. برای اجرا روی پورت دیگر: `npm.cmd start -- --hostname 127.0.0.1 --port 3001`.

برای توسعه: `npm run dev`. بعد از تغییر سورس برای اجرای production دوباره `npm run build` لازم است.

## استفاده از موبایل و استقرار شبکه

واکنش‌گرایی به معنی دسترسی خودکار موبایل به localhost کامپیوتر نیست. برای استفاده در شبکه باید سرور روی رابط شبکه قابل دسترس باشد، مجوز فایروال تنظیم شود و آدرس میزبان از موبایل باز شود. برای اطلاعات واقعی **HTTPS** و reverse proxy مناسب تنظیم کنید و در `.env` مقدار `COOKIE_SECURE="true"` بگذارید. سپس برنامه را بازراه‌اندازی کنید. مقدار `false` فقط برای آزمایش محلی HTTP است.

محدودیت ورود داخلی جایگزین محدودسازی نرخ درخواست در reverse proxy نیست. این نسخه بازیابی رمز از طریق ایمیل یا احراز هویت دومرحله‌ای ندارد؛ مدیر رمز کاربران را از صفحه کاربران تغییر می‌دهد. پایگاه داده را عمومی نکنید، از `.env` حفاظت کنید و پشتیبان‌گیری منظم داشته باشید. سورس کنترل، کلید نشست و رمزها را شامل نشود.

## بررسی‌ها و محدودیت تأیید

در محیط ساخت لینوکسی:

- `prisma validate`: موفق.
- `prisma generate`: موفق.
- `npm run typecheck`: موفق.
- `npm run build`: موفق؛ همه صفحات برنامه کامپایل شدند.
- `npm run test:smoke`: موفق؛ نمایش فرم ورود فارسی RTL، سرآیندهای امنیتی و هدایت ۱۳ مسیر محافظت‌شده برای کوکی غایب/نامعتبر.
- نصب‌کننده Bash: بررسی نحو و استخراج آزمایشی موفق.

**در این محیط سرور MySQL و PowerShell موجود نبود؛ اجرای migration روی MySQL واقعی، عملیات CRUD، تست هم‌زمانی، تعامل مرورگر و اجرای نصب‌کننده روی ویندوز هنوز آزمایش نشده‌اند.** موفقیت build معادل تأیید این موارد نیست.

قبل از ورود داده واقعی، چک‌لیست `TESTING.fa.md` را انجام دهید. پس از بیلد می‌توانید تست محدود HTTP را با `npm run test:smoke` تکرار کنید؛ این تست به دیتابیس وصل نمی‌شود.

## خطاهای متداول

- `P1001`: MySQL روشن نیست یا host/port اشتباه است.
- `P1000` / Access denied: رمز، نام کاربر، میزبان حساب MySQL یا مجوزهای دیتابیس را بررسی کنید.
- دیتابیس غیرخالی: برای نصب اولیه دیتابیس خالی و اختصاصی استفاده کنید؛ روی دیتابیس برنامه دیگر migration اجرا نکنید.
- `ECONNRESET`: مشکل اتصال npm؛ اینترنت/پروکسی را اصلاح و setup را تکرار کنید. اعتبارسنجی TLS را غیرفعال نکنید.
- `ENOSPC`: فضای آزاد و تعداد فایل‌های قابل ایجاد را بررسی کنید.
- خطای اجرای `npm.ps1`: در PowerShell از `npm.cmd` استفاده کنید؛ setup ویندوز از همین فرمان استفاده می‌کند.
- بازگشت مداوم به ورود روی HTTP: مطمئن شوید `COOKIE_SECURE=false` فقط برای محیط محلی تنظیم شده است.
- پورت اشغال است: با `--port 3001` اجرا کنید.

**هرگز برای رفع خطای نصب روی دیتابیس دارای اطلاعات از `prisma migrate reset` یا حذف جدول استفاده نکنید.**
